You can initiate in-store POS payments directly onto a merchant terminal using PayU's Server-to-Server `v2/payments` API. This section provides the request and response parameters used in Step 1 of [POS Integration - V2 Payments API](doc:pos-integration-v2-payments-api). You can get the sample request and response when using the "Try It" experience. For the complete integration steps, refer to [POS Integration - V2 Payments API](doc:pos-integration-v2-payments-api).

### Body Parameters

<Accordion title="Body Parameters" icon="fa-table">
  **Mandatory parameters**

  | Parameter            | Description                                                                                                                                            | Example              |
  | :------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------- |
  | `accountId`          | `String` Merchant account identifier configured in PayU.                                                                                               | `smsplus`            |
  | `txnId`              | `String` Unique transaction identifier generated by merchant billing system.                                                                           | `POS_TXN_987654321`  |
  | `amount`             | `Number / String` Transaction amount in INR.                                                                                                           | `10.00` or `"10.00"` |
  | `currency`           | `String` ISO currency code. Must be `INR`.                                                                                                             | `INR`                |
  | `paymentSource`      | `String` Source channel identifier (`POS` or `WEB`).                                                                                                   | `POS`                |
  | `paymentMethod`      | `Object` Payment mode object. For details, refer to the [`paymentMethod` Object](#paymentmethod-object).                                               |                      |
  | `additionalInfo`     | `Object` Flow configuration object. For details, refer to the [`additionalInfo` Object](#additionalinfo-object).                                       |                      |
  | `callBackActions`    | `Object` Callback URL specifications. For details, refer to the [`callBackActions` Object](#callbackactions-object).                                   |                      |
  | `order`              | `Object` Order details, user-defined fields, and price specifications. For details, refer to the [`order` Object](#order-object).                      |                      |
  | `omniChannelDetails` | `Object` POS terminal targeting parameters and print information. For details, refer to the [`omniChannelDetails` Object](#omnichanneldetails-object). |                      |

  **Optional parameters**

  | Parameter   | Description                                                                                                                         | Example |
  | :---------- | :---------------------------------------------------------------------------------------------------------------------------------- | :------ |
  | `gstParams` | `Object` GST tax breakdown, invoice number, and tax percentages. For details, refer to the [`gstParams` Object](#gstparams-object). |         |

  ### `paymentMethod` Object

  **Mandatory parameters**

  | Parameter  | Description                     | Example |
  | :--------- | :------------------------------ | :------ |
  | `name`     | `String` Always set to `"POS"`. | `POS`   |
  | `bankCode` | `String` Always set to `"POS"`. | `POS`   |

  ### `additionalInfo` Object

  **Mandatory parameters**

  | Parameter    | Description                                                    | Example    |
  | :----------- | :------------------------------------------------------------- | :--------- |
  | `txnFlow`    | `String` Flow type. Always set to `"seamless"`.                | `seamless` |
  | `txnS2sFlow` | `String` Server-to-server flow indicator. Always set to `"4"`. | `4`        |

  ### `omniChannelDetails` Object

  **Mandatory parameters**

  | Parameter     | Description                                        | Example |
  | :------------ | :------------------------------------------------- | :------ |
  | `posDeviceId` | `String` Registered PayU POS Terminal / Device ID. | `134`   |

  **Optional parameters**

  | Parameter          | Description                                                                                                                                  | Example       |
  | :----------------- | :------------------------------------------------------------------------------------------------------------------------------------------- | :------------ |
  | `posPaymentMethod` | `String` Payment method to enforce on POS screen: `sale`, `qr`, `wallet`, `emi`, `preauth`. If omitted, all supported options are displayed. | `sale`        |
  | `userId`           | `String` Operator / Cashier ID associated with the terminal session.                                                                         | `cashier_102` |
  | `printInfo`        | `Object` Key-value strings (e.g., `printInfo1`, `printInfo2`) printed on the POS physical receipt.                                           |               |

  ### `order` Object

  **Mandatory parameters**

  | Parameter                          | Description                                                       | Example |
  | :--------------------------------- | :---------------------------------------------------------------- | :------ |
  | `paymentChargeSpecification.price` | `Number / String` Payable amount matching the top-level `amount`. | `10.00` |

  **Optional parameters**

  | Parameter           | Description                                              | Example                    |
  | :------------------ | :------------------------------------------------------- | :------------------------- |
  | `productInfo`       | `String` Description of goods or services purchased.     | `In-Store Retail Purchase` |
  | `userDefinedFields` | `Object` Custom metadata fields (`udf1` through `udf5`). |                            |

  ### `callBackActions` Object

  **Mandatory parameters**

  | Parameter       | Description                                   | Example                        |
  | :-------------- | :-------------------------------------------- | :----------------------------- |
  | `successAction` | `String` Redirect / callback URL for success. | `https://yoursite.com/success` |

  **Optional parameters**

  | Parameter       | Description                                        | Example                        |
  | :-------------- | :------------------------------------------------- | :----------------------------- |
  | `failureAction` | `String` Redirect / callback URL for failure.      | `https://yoursite.com/failure` |
  | `cancelAction`  | `String` Redirect / callback URL for cancellation. | `https://yoursite.com/cancel`  |

  ### `gstParams` Object

  **Optional parameters**

  | Parameter       | Description                                        | Example                     |
  | :-------------- | :------------------------------------------------- | :-------------------------- |
  | `invoiceNo`     | `String` Invoice number for the purchase.          | `INV-1234`                  |
  | `invoiceDate`   | `String` Invoice timestamp in ISO 8601 format.     | `2026-10-07T14:30:00+05:30` |
  | `invoiceName`   | `String` Title/name on invoice.                    | `Store Invoice`             |
  | `gstIn`         | `String` Merchant GSTIN.                           | `08TESTF0078P1ZP`           |
  | `gst`           | `Number / String` Total GST amount.                | `10`                        |
  | `cgst`          | `Number / String` Central GST component amount.    | `10`                        |
  | `sgst`          | `Number / String` State GST component amount.      | `40`                        |
  | `igst`          | `Number / String` Integrated GST component amount. | `50`                        |
  | `cess`          | `Number / String` Cess amount.                     | `60`                        |
  | `gstIncentive`  | `Number / String` GST incentive value.             | `12.5`                      |
  | `gstPercentage` | `Number / String` Total applied GST percentage.    | `50`                        |
</Accordion>

<Accordion title="Response parameters" icon="fa-list">
  | **Parameter**             | **Description**                                                                                  |
  | :------------------------ | :----------------------------------------------------------------------------------------------- |
  | `metaData`                | `JSON` JSON object containing status and transaction identification metadata.                    |
  | `metaData.txnId`          | `String` The unique merchant transaction ID passed in the request.                               |
  | `metaData.referenceId`    | `String` Encoded unique transaction reference ID generated by PayU.                              |
  | `metaData.statusCode`     | `String` PayU API status code (e.g., `E000` for success, `E342`, `E2081`, `EX158` for failures). |
  | `metaData.txnStatus`      | `String` High-level status of the transaction (`pending`, `failed`).                             |
  | `metaData.unmappedStatus` | `String` Detailed stage status of the transaction (`pending`, `failure`).                        |
  | `metaData.message`        | `String` Human-readable status or error description.                                             |
  | `result`                  | `JSON` JSON object containing payment identifiers and authorization actions.                     |
  | `result.paymentId`        | `String` Unique PayU Payment ID assigned to the transaction.                                     |
  | `result.authAction`       | `String` OTP / authentication action URL if applicable.                                          |
  | `result.otpPostUrl`       | `String` POST endpoint for OTP submission if applicable.                                         |

  For more details, refer to [Status Codes and Error Handling](ref:error-codes).
</Accordion>

<Accordion title="Server-to-Server Webhook Response" icon="fa-bell">
  Once the payment is completed or canceled on the terminal, PayU triggers an asynchronous S2S webhook to your configured webhook URL.

  ### Sample Webhook Payload

  ```json
  {
    "vendorTxnId": "1499262399",
    "txnId": "POS_TXN_987654321",
    "mihpayId": 27447252485,
    "flowType": "Integrated",
    "message": "Transaction Captured Successfully",
    "status": "captured"
  }
  ```

  | **Parameter** | **Description**                                           |
  | :------------ | :-------------------------------------------------------- |
  | `vendorTxnId` | `String` PayU terminal vendor transaction reference.      |
  | `txnId`       | `String` Merchant's unique transaction ID.                |
  | `mihpayId`    | `Number` PayU Payment identifier.                         |
  | `flowType`    | `String` Integration mode (`Integrated`).                 |
  | `status`      | `String` Final transaction status (`captured`, `failed`). |
  | `message`     | `String` Result message.                                  |
</Accordion>

<Callout icon="🚧" theme="warn">
  ### Error Handling:

  A list of error messages with corresponding error codes (`E000`, `E342`, `E2081`, `EX158`, `E1101`) and resolutions are available. PayU recommends handling these errors synchronously during initiation and reconciling terminal outcomes via Webhooks and Status Check APIs. For more information, refer to [Error Codes](ref:error-codes).
</Callout>
