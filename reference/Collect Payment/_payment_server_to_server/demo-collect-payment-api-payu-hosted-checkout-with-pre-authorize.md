Use the Collect Payment (**\_payment**) API with **PayU Hosted Checkout** to start a **pre-authorized** card transaction. Set `pre_authorize` to `1` so funds are held (authorized) until you [capture](ref:capture_a_payment) or [cancel](ref:cancel-a-pre-authorized-transaction) the transaction.

Customers complete payment on PayU’s hosted page. On success, PayU redirects to your `surl` or `furl` with postback parameters. For a successful pre-auth, **`unmappedstatus`** is **`auth`** (not `captured`).

**Environment**

| | |
| :-- | :-- |
| Test | `https://test.payu.in/_payment` |
| Production | `https://secure.payu.in/_payment` |

**HTTP Method**: `POST`

**Content-Type**: `application/x-www-form-urlencoded`

<Accordion title="Request parameters" icon="fa-table">

| Parameter | Description | Example |
| --------- | ----------- | ------- |
| key<br /><code>mandatory</code> | <code>String</code> Merchant key from PayU. Use your test key in the test environment. | JPM7Fg |
| txnid<br /><code>mandatory</code> | <code>String</code> Unique order reference generated by you. Duplicate values are rejected. | PQI6MqpYrjEefU |
| amount<br /><code>mandatory</code> | <code>String</code> Transaction amount (decimal allowed, e.g. <code>10.00</code>). | 10.00 |
| productinfo<br /><code>mandatory</code> | <code>String</code> Short description of the product or order. | iPhone |
| firstname<br /><code>mandatory</code> | <code>String</code> Customer first name. | PayU User |
| email<br /><code>mandatory</code> | <code>String</code> Customer email. | test@gmail.com |
| phone<br /><code>mandatory</code> | <code>String</code> Customer mobile number. | 9876543210 |
| pre_authorize<br /><code>mandatory</code> | <code>String</code> Set to <code>1</code> to pre-authorize on PayU Hosted Checkout. | 1 |
| hash<br /><code>mandatory</code> | <code>String</code> Request hash computed at your server. See [Hash](#hash) below. | (computed) |
| surl | <code>String</code> Success redirect URL after payment. | https://merchant.example/success |
| furl | <code>String</code> Failure redirect URL after payment. | https://merchant.example/failure |
| curl | <code>String</code> Cancel redirect URL if the customer cancels checkout. | https://merchant.example/cancel |
| lastname | <code>String</code> Customer last name (alphabets only). | User |
| udf1 – udf5 | <code>String</code> Optional merchant-defined fields echoed in the response. | |

### Hash

```
sha512(key|txnid|amount|productinfo|firstname|email|udf1|udf2|udf3|udf4|udf5||||||SALT)
```

For key and salt generation, refer to [Generate Merchant Key and Salt](doc:generate-merchant-key-and-salt-on-payu-dashboard) (production) or [Generate Test Merchant Key and Salt](doc:generate-test-merchant-key-and-salt) (test).

</Accordion>

<Accordion title="Sample request" icon="fa-code">

```curl
curl -X POST "https://test.payu.in/_payment?form=2" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "key=JP***g&txnid=PQI6MqpYrjEefU&amount=10.00&productinfo=iPhone&firstname=PayU User&email=test@gmail.com&phone=9876543210&pre_authorize=1&surl=https://apiplayground-response.herokuapp.com/&furl=https://apiplayground-response.herokuapp.com/&hash=05a397501918ec5c36ae52daa3b3e49b43e986b86940e109d060076e467c3ea7536617df7420e0e6863dced8c5b45f9fff15c13bdf0335512c05f0210b31b072"
```

</Accordion>

<Accordion title="Sample response" icon="fa-reply">

PayU returns **HTML** for hosted checkout (browser redirect). After the customer pays, parameters are posted to `surl` or `furl` as **application/x-www-form-urlencoded** text.

**Pre-authorize success indicators**

- `status`: `success`
- `unmappedstatus`: **`auth`** (authorized, not yet captured)
- `mihpayid`: PayU transaction ID (use for capture/cancel)

```text
mihpayid=403993715523615328&mode=CC&status=success&unmappedstatus=auth&key=JPM7Fg&txnid=50QJq6lBJBmx14&amount=10.00&productinfo=iPhone&firstname=PayU User&email=test@gmail.com&phone=9876543210&error=E000&error_Message=No Error&PG_TYPE=CC-PG&bankcode=CC
```

</Accordion>

<Accordion title="Response parameters" icon="fa-table">

| Parameter | Description |
| --------- | ----------- |
| mihpayid | PayU transaction ID. Use as `payuid` in [Capture a Pre-Authorized Payment](ref:capture_a_payment) and [Cancel a Pre-Authorized Transaction](ref:cancel-a-pre-authorized-transaction). |
| status | Order status: `success`, `failure`, or `pending`. Treat only `success` with `unmappedstatus=auth` as a successful pre-authorization. |
| unmappedstatus | PayU internal status. For pre-auth success, expect **`auth`**. After capture, this becomes `captured`. |
| mode | Payment mode (e.g. `CC` for credit card, `DC` for debit card). |
| bankcode | Payment option code (e.g. `CC`, `VISA`). |
| txnid | Your transaction ID from the request. |
| amount | Amount sent in the request. |
| key | Merchant key echoed in the response. |
| hash | Response hash for verification. Validate using your response hash logic. |
| error | Error code; `E000` when there is no error. |
| error_Message | Human-readable error message. |
| PG_TYPE | Payment gateway type used (e.g. `CC-PG`). |
| bank_ref_num | Bank reference number when available. |
| productinfo, firstname, lastname, email, phone | Echo of request fields. |
| udf1 – udf5 | Echo of user-defined fields when sent. |

For additional postback fields and status meanings, refer to [Collect Payment API - PayU Hosted Checkout](ref:_payment_payu_hosted_checkout) and [Payment State Explanations](ref:payment-state-explanations).

</Accordion>
