The **Create Transaction API** executes the card authorization step. When using PayU Cards Element, this call is typically orchestrated automatically under the hood by the client-side JavaScript SDK (`PayuCheckout.processPayment()`). 

For server-to-server or custom checkout architectures, merchants invoke this endpoint with either plain card credentials (for PCI DSS SAQ D environments) or network-tokenized card parameters.

## Authentication & Headers

Requests to `/v1/payment` require session credentials generated by the Create Order API (`POST /v1/checkout/l1`).

### Authentication Modes

1. **Option A (Recommended)**: Pass `encOrderId` and `accessToken`.
2. **Option B**: Pass `orderId`, `X-Credential-Username`, and `accessToken`.

### Request Headers

| Header | Description |
| :--- | :--- |
| Content-Type | _String_<br>Must be set to `application/json`. |
| accessToken | _String_<br>Ephemeral session token obtained from `result.transaction.accessToken` in the Create Order response. |
| encOrderId | _String_<br>Encrypted order ID obtained from `result.transaction.encryptedOrderId` in the Create Order response.<br>_Alternative:_ Pass `orderId` paired with the `X-Credential-Username` header. |

---

## Request Parameters

### Mandatory Parameters

| Parameter | Description |
| :--- | :--- |
| paymentMethod | _Object_<br>Container object holding payment instrument specifications, card credentials, or token details. |

---

#### Nested Object: paymentMethod.card (Plain Physical Card)

> ⚠️ **PCI DSS SAQ D Notice**
> Transmitting raw card numbers and CVV via direct server-to-server calls requires full PCI DSS Level 1 SAQ D compliance. For low-PCI scope (SAQ A), use the client-side Cards Element JS SDK.

**Mandatory Parameters**

| Parameter | Description |
| :--- | :--- |
| cardNumber | _String_<br>Primary Account Number (PAN) of the credit or debit card without spaces or hyphens (13 to 19 digits). |
| validThrough | _String_<br>Card expiration date formatted as `MM/YY` or `MM/YYYY`. |
| cvv | _String_<br>Card Verification Value / Security Code (3 digits for Visa, Mastercard, and RuPay; 4 digits for American Express). |
| ownerName | _String_<br>Name of the cardholder as embossed on the card. |

**Optional Parameters**

| Parameter | Description |
| :--- | :--- |
| storeCard | _String_<br>Consent to tokenize and save the card for repeat checkout (Card-on-File). Pass `"1"` to save the card, or `"0"` for a one-time transaction. Default is `"0"`. |

---

#### paymentMethod.card (Stored / Tokenized Card)

**Mandatory Parameters**

| Parameter | Description |
| :--- | :--- |
| storeCardToken | _String_<br>Card-on-File network token or PayU token identifying the saved card. |
| cvv | _String_<br>Card security code associated with the tokenized card. |

**Optional Parameters**

| Parameter | Description |
| :--- | :--- |
| storecardTokenType | _String_<br>Type identifier for the stored token. Pass `"1"` for PayU network tokens. |

## Sample Request

### 1. Plain Card Request

```json
{
  "paymentMethod": {
    "card": {
      "cardNumber": "4012001033842188",
      "validThrough": "12/28",
      "cvv": "123",
      "ownerName": "John Doe",
      "storeCard": "0"
    }
  }
}
```

### 2. Tokenized Card Request

```json
{
  "paymentMethod": {
    "card": {
      "storeCardToken": "4892749283749284",
      "storecardTokenType": "1",
      "cvv": "123"
    }
  }
}
```

## Response Structure & 3DS Challenge

When card payment authorization requires customer two-factor authentication (3DS OTP challenge), the API returns HTTP 200 with `result.metaData.txnStatus: "Enrolled"` and a Base64-encoded HTML form in `result.acsTemplate`.

### Sample 3DS Challenge Response

```json
{
  "status": 0,
  "message": "Transaction initiated",
  "result": {
    "acsTemplate": "PGh0bWw+PGJvZHkgb25sb2FkPSJkb2N1bWVudC5mb3Jtcy5wb3N0Zm9ybS5zdWJtaXQoKSI+PGZvcm0gbmFtZT0icG9zdGZvcm0iIG1ldGhvZD0icG9zdCIgYWN0aW9uPSJodHRwczovL2Fjcy5iYW5rLmV4YW1wbGUuY29tLzNkcy9hdXRoIj48aW5wdXQgdHlwZT0iaGlkZGVuIiBuYW1lPSJQYVJlcSIgdmFsdWU9Ii4uLiIgLz48L2Zvcm0+PC9ib2R5PjwvaHRtbD4=",
    "metaData": {
      "referenceId": "18492048291",
      "txnStatus": "Enrolled",
      "paymentMode": "CC"
    }
  }
}
```

### Handling 3DS Redirection in Web Applications

To forward the customer to the bank's 3DS authentication portal:
1. Decode the Base64 string in `result.acsTemplate`.
2. Inject the decoded HTML form into the DOM.
3. Automatically submit the form to redirect the customer's browser.

```javascript JavaScript
// Decode Base64 ACS form and submit
const decodedHtml = atob(response.result.acsTemplate);
const container = document.createElement('div');
container.innerHTML = decodedHtml;
document.body.appendChild(container);
container.querySelector('form').submit();
```
