        Common errors & troubleshooting
        

          
    
            
  • Amount is required / invalid decimal — Enter a numeric value (e.g. 10 or 10.00). Remove spaces, commas, or currency symbols. Use a dot for decimals.
    • 
            
  • Merchant key / SALT is required — Get key and salt from PayU Dashboard (API Keys). Use test key/salt for testing. Never send SALT in the payment request.
    • 
            
  • SALT error despite entering value — Some browsers don’t expose password fields to script when the page is opened via file://. Tick “Show SALT” or serve the page from a local server (e.g. python -m http.server 8080).
    • 
            
  • Email is required / invalid email — Enter a valid email (e.g. user@example.com). Must match the value you send in the payment request.
    • 
            
  • Transaction ID is required — Use a unique ID per transaction (e.g. order ID or UUID). Same value must be sent in the payment request.
    • 
            
  • Hash mismatch on PayU — Ensure (1) you use the correct key and salt for the environment (test vs production), (2) parameter order matches: key|txnid|amount|productinfo|firstname|email|udf1|udf2|udf3|udf4|udf5||||||salt, (3) no extra spaces; trim values the same way on your server, (4) amount format matches (e.g. 10.00 not 10.00 INR).
    • 
            
  • Wrong merchant / key mix-up — Do not use Merchant ID (MID) in place of Merchant Key. Do not swap key and salt. Check PayU Dashboard for the correct key and salt.
    • 
            
  • Wrong hash formula — Use the Hash logic dropdown to match your flow (payment request vs response; split / additional charges). Formulas follow PayU – Generate Hash (PayU Hosted). For v19, confirm api_version=19 with PayU if your string differs.
