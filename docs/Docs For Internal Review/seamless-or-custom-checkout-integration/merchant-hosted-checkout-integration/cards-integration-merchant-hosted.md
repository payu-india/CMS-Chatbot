Merchant Hosted Checkout enables you to securely accept **credit and debit card** payments on your own checkout UI.

<Callout icon="👍" theme="okay">
  ### **Payment Flow**

  Customer enters card details on your checkout → your server hashes and posts to PayU → 3DS/OTP as required → PayU returns to your `surl`/`furl` → you verify on the backend.
</Callout>

***

## Prerequisites


- PayU merchant account with cards enabled
- Test and production Key and Salt
- Unique `txnid`
- Public HTTPS `surl` and `furl`
- Server-side SHA-512 hash generation
- PCI-aware card data handling (never store CVV; do not log PAN)


***

## Supported Payment Methods


This page covers:

- Credit Cards
- Debit Cards


***

## 1. Build Integration

Below are the steps to build this integration:


1. Prepare payment request parameters (including card fields)
2. Generate a secure hash
3. Post the payment from your checkout to PayU
4. Verify the response via reverse hashing
5. Verify the payment status


***

### Step 1.1 Prepare Payment Request Parameters

Collect and structure the parameters before initiating a transaction.


<Accordion title="Mandatory Parameters and Description" icon="fa-table">

| Parameter     | Description | Example |
| ------------- | ----------- | ------- |
| `key`         | `string` Merchant key provided by PayU during onboarding. | `JPG****k` |
| `txnid`       | `string` Unique transaction/order reference generated by you. | `txn_1234` |
| `amount`      | `string` Payment amount (two decimal places). | `10.00` |
| `productinfo` | `string` Brief product description. | `iPhone` |
| `firstname`   | `string` Customer first name. | `Aarav` |
| `email`       | `string` Customer email. | `aarav@example.com` |
| `phone`       | `string` Customer phone. | `9876543210` |
| `surl`        | `string` Success return URL. | `https://yourwebsite.com/success` |
| `furl`        | `string` Failure return URL. | `https://yourwebsite.com/failure` |
| `hash`        | `string` SHA-512 hash generated on your server. | `GENERATED_HASH` |

  | `pg` | `string` Payment mode for cards. | `CC` |
  | `bankcode` | `string` Card bank/scheme code as applicable. | `CC` |
  | `ccnum` | `string` Card number (validate with Luhn). | `5123456789012346` |
  | `ccname` | `string` Name on card. | `Ashish Kumar` |
  | `ccvv` | `string` CVV / security code. | `123` |
  | `ccexpmon` | `string` Expiry month (`MM`). | `10` |
  | `ccexpyr` | `string` Expiry year (`YYYY`). | `2026` |
</Accordion>

<Accordion title="Optional Advanced Parameters and Description" icon="fa-table">

| Parameter | Description | Example |
| --------- | ----------- | ------- |
| `lastname` | `string` Customer last name. | `Kumar` |
| `address1` / `address2` / `city` / `state` / `country` / `zipcode` | Billing address fields (useful for fraud and some modes). | `Mumbai` |
| `udf1`–`udf5` | `string` User-defined fields. Keep empty pipe slots in hash when unused. | `order-42` |
| `curl` | `string` Cancel URL. | `https://yourwebsite.com/cancel` |

</Accordion>


***


### Step 1.2: Generate Secure Hash

To ensure the payment request is secure, generate a hash using your transaction details and merchant credentials. Hash protects the request from tampering.

<Accordion title="Steps to Generate Hash" icon="fa-key">
  Concatenate these parameters in order:

  * `key`
  * `txnid`
  * `amount`
  * `productinfo`
  * `firstname`
  * `email`
  * `salt`

  ```Text Logic
  key|txnid|amount|productinfo|firstname|email|||||||||||salt
  ```
  ```Text Example Values
  YOUR_KEY|txn_123456|10.00|TestProduct|Test|test@example.com|||||||||||salt_value
  ```

  <Callout icon="⚠️" theme="warn">
**Critical Rules**

- Generate hash only on your backend
- Do not change parameter order
- Do not skip pipes (`|`); keep empty UDF positions
- No extra spaces; encode as UTF-8 before hashing
  </Callout>
</Accordion>


***

### Step 1.3 Post Payment from Your Checkout


Post card parameters from your server-backed checkout to PayU.

| **Environment**            | **URL**                         |
| :------------------------- | :------------------------------ |
| **Test Environment**       | `https://test.payu.in/_payment` |
| **Production Environment** | `https://secure.payu.in/_payment` |

<Accordion title="Sample request" icon="fa-code">
  ```curl
  curl -X POST "https://test.payu.in/_payment" \
    -H "Content-Type: application/x-www-form-urlencoded" \
    -d "key=YOUR_KEY" \
    -d "txnid=txn_card_001" \
    -d "amount=10.00" \
    -d "productinfo=iPhone" \
    -d "firstname=Ashish" \
    -d "email=test@gmail.com" \
    -d "phone=9876543210" \
    -d "pg=CC" \
    -d "bankcode=CC" \
    -d "ccnum=5123456789012346" \
    -d "ccname=Ashish Kumar" \
    -d "ccvv=123" \
    -d "ccexpmon=10" \
    -d "ccexpyr=2026" \
    -d "surl=https://yourwebsite.com/success" \
    -d "furl=https://yourwebsite.com/failure" \
    -d "hash=GENERATED_HASH"
  ```
</Accordion>

#### What Next - Customer Journey

1. Issuer may present 3DS / OTP
2. Customer completes authentication
3. PayU returns to your `surl` or `furl`


***


### Step 1.4 Verify Response via Reverse Hashing

After you receive a response, verify it via reverse hashing. This is a critical step to verify the authenticity of the payment.

<Accordion title="Reverse hashing checklist" icon="fa-shield-halved">
  For every callback/response:

  1. Receive response parameters
  2. Extract the response `hash`
  3. Generate reverse hash using PayU reverse-hash logic
  4. Compare hashes
  5. Reject mismatches

  For full reverse-hash formulas, see [Hashing request and response](doc:hashing-request-and-response).
</Accordion>


***


### Step 1.5 Verify the Payment

After the transaction is done, verify the payment status as a final step.

<Callout icon="⚠️" theme="warn">
  **Important**

  Never mark an order as paid from browser redirect alone. Confirm with [Verify Payment API](ref:verify_payment_api) and/or [Webhooks](doc:webhooks).
</Callout>


***

### Handling Guest Checkout Transactions

For guest checkout, still collect mandatory customer fields (`firstname`, `email`, `phone`) and keep `txnid` unique per attempt.

***

### Handling 3DS Secure 2.0 Transaction

When the issuer requires 3DS 2.0, PayU orchestrates frictionless/challenge flows. Fulfil only after backend verification, even if the browser returns quickly.


***


## 2. Test Integration

Use the PayU test environment before production.

| **Environment**            | **URL**                         |
| :------------------------- | :------------------------------ |
| **Test Environment**       | `https://test.payu.in/_payment` |
| **Production Environment** | `https://secure.payu.in/_payment` |

### Step 2.1 Simulate a Successful Transaction

1. Post a valid test payment for this mode
2. Complete authentication using [test credentials](doc:test-cards-upi-id-and-wallets)
3. Land on `surl`
4. Validate reverse hash and Verify Payment status = success

### Step 2.2 Simulate a Failed Transaction

1. Force a decline / invalid credential / customer cancel path
2. Confirm `furl` handling
3. Confirm your order stays unpaid when Verify Payment is not success


***


## 3. Go-live Checklist

<Accordion title="Credentials and endpoint" icon="fa-key">
  - Switch to production Key and Salt
  - Post to `https://secure.payu.in/_payment`
  - Never mix test Salt with production URL
</Accordion>

<Accordion title="Security" icon="fa-lock">
  - Hash only on backend
  - Reverse hash on every response
  - No PAN/CVV/Salt in logs or client code
</Accordion>

<Accordion title="Operations" icon="fa-clipboard-check">
  - Webhooks configured
  - Verify Payment fallback implemented
  - Mode enabled on production MID
</Accordion>


***


## Errors and Troubleshooting

<Accordion title="Invalid Hash" icon="fa-triangle-exclamation">
  - Check parameter order and pipe count
  - Remove extra spaces / newlines
  - Confirm UTF-8 encoding and correct Salt
</Accordion>

<Accordion title="Payment not completing" icon="fa-triangle-exclamation">
  - Confirm endpoint and HTTP POST
  - Confirm mode-specific `pg` / `bankcode` (and mode fields)
  - Confirm `surl` / `furl` are publicly reachable
</Accordion>

<Accordion title="Success UX but unpaid order" icon="fa-triangle-exclamation">
  - Do not trust redirect alone
  - Use reverse hash + Verify Payment / webhooks
</Accordion>
