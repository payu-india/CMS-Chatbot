The Decoupled Authentication using S2S4 with `auth_only=2` integration involves the following steps:

<Cards>
  <Card title="1. Initiate payment request with PayU" href="#step-1-initiate-payment-request-with-payu">
    Create and send a payment request to PayU with all required parameters and merchant configuration
  </Card>

  <Card title="2. Check Authentication Status" href="#step-2-check-authentication-status">
    Call the AuthData API to retrieve 3DS2 authentication results
  </Card>
</Cards>

<RegisterMerchantPrerequiste />

> 📘 Notes:
>
> * This flow is specifically for `auth_only=2` where merchants need to call the AuthData API to get authentication results.
> * For `auth_only=1` flow (with automatic authorization), refer to <Anchor label="Decoupled Flow Integration" target="_blank" href="integrate-with-decoupled-flow-s2s">Decoupled Flow Integration</Anchor>.
> * If you are using legacy integration of decoupled flow for S2S, refer to <Anchor label="Legacy Flow for Server-to-Server" target="_blank" href="legacy-flow-for-server-to-server">Legacy Flow for Server-to-Server</Anchor>.

## Step 1: Initiate payment request with PayU

The merchant initiates PayU with the required transaction mandatory or optional parameters. This needs to be a server-to-server curl call request. URL, parameters, and their descriptions. For more information, refer to <Anchor label="Cards Decoupled Flow" target="_blank" href="ref:_payment_s2s_decoupled_flow">Cards Decoupled Flow</Anchor>.

## Step 2: Check Authentication Status

Unlike `auth_only=1` flow, when using `auth_only=2`, you must call the **AuthData API** to retrieve the 3DS2 authentication results. This is because 3DS2.0 cannot return the authentication response via the browser.

For detailed API specifications, refer to [AuthData API Reference](ref:auth-data-api).

<Accordion title="API Endpoint" icon="fa-server">
  | Environment | URL                                         |
  | ----------- | ------------------------------------------- |
  | Test        | `https://test.payu.in/decoupled/AuthData`   |
  | Production  | `https://secure.payu.in/decoupled/AuthData` |
</Accordion>

<Accordion title="Query Parameter" icon="fa-code">
  | Parameter   | Description                                        | Example                          |   |
  | ----------- | -------------------------------------------------- | -------------------------------- | - |
  | referenceId | Reference ID provided by PayU (as in Step 1 above) | 00c44a4c8306f9cbe5ecf6133afe08a7 |   |
</Accordion>

<Accordion title="Request Headers" icon="fa-code">
  | Parameter    | Description                                               | Example                       |
  | ------------ | --------------------------------------------------------- | ----------------------------- |
  | key          | Merchant key provided by PayU                             | smsplus                       |
  | hash         | SHA512 hash: \`sha512(key\\\|mihpayid\\\|admin\\\|date)\` |                               |
  | Date         | Current date in UTC format                                | Tue, 07 Mar 2023 10:46:50 GMT |
  | Content-Type | Required for POST requests (Type 2)                       | application/json              |
</Accordion>
