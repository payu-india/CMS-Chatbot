Net Banking – Quick Checkout is an innovative payment solution designed to streamline the traditional Net Banking payment process. By implementing an OTP-only checkout flow, it eliminates the need for customers to enter full Net Banking credentials, reducing transaction abandonment and improving conversion rates.

<Note>
  This flow is currently supported for **ICICI Quick Checkout** and select wallet partners. Subsequent transactions utilize a securely stored Federated ID (`FEDID`) and Token in PayU's Store Card service.
</Note>

## Step 1: Customer Registration & Tokenization
To enable Quick Checkout, the customer must first complete a one-time registration process. During this initial redirection flow, the bank validates the customer and returns a Federated ID (`FEDID`) and a secure `Token`.

### Step Title: Register Customer for Quick Checkout
* **What you need:** Customer's basic details, merchant credentials, and redirection URLs (`surl`/`furl`).
* **Instructions:** Redirect the customer to the bank's portal to complete their first Net Banking transaction. Upon successful authentication, the bank generates the registration credentials.
* **Checkpoint:** ✅ PayU securely stores the returned `FEDID` and `Token` in the Store Card service mapped against the customer's unique identifier.

---

## Step 2: Initiate Quick Checkout Payment
For returning registered customers, you can initiate an OTP-only transaction directly from your server.

### Step Title: Post Payment Request to PayU
* **What you need:** Stored customer token, transaction details, and standard payment parameters.
* **Instructions:** Send a POST request to PayU's `_payment` endpoint.
* **Checkpoint:** ✅ The response will return transaction status details and trigger an OTP to the customer's registered mobile number.

### Request Parameters
| Parameter | Type & Description | Example |
| :--- | :--- | :--- |
| `key` <br/>_mandatory_ | `String` Merchant key provided by PayU. | `JPg***r` |
| `txnid` <br/>_mandatory_ | `String` Unique transaction ID generated by the merchant. | `txnid938459435` |
| `amount` <br/>_mandatory_ | `String` Transaction amount. | `1000.00` |
| `pg` <br/>_mandatory_ | `String` Payment category. Use `NB` for Net Banking. | `NB` |
| `bankcode` <br/>_mandatory_ | `String` Bank code for the Quick Checkout bank. | `ICICIB` |
| `user_credentials` <br/>_mandatory_ | `String` Unique identifier mapping the user (`merchantKey:userId`). | `JPg***r:user123` |

<Accordion title="Sample Request & Response" icon="fa-code">

```bash
curl --location --request POST 'https://test.payu.in/_payment' \
--header 'Content-Type: application/x-www-form-urlencoded' \
--data-urlencode 'key=JPg***r' \
--data-urlencode 'txnid=txnid938459435' \
--data-urlencode 'amount=1000.00' \
--data-urlencode 'firstname=Ashish' \
--data-urlencode 'email=test@gmail.com' \
--data-urlencode 'phone=9988776655' \
--data-urlencode 'productinfo=iPhone' \
--data-urlencode 'pg=NB' \
--data-urlencode 'bankcode=ICICIB' \
--data-urlencode 'surl=`https://your-success-url.com`' \
--data-urlencode 'furl=`https://your-failure-url.com`' \
--data-urlencode 'user_credentials=JPg***r:user123' \
--data-urlencode 'hash=eabec285da28fd0e3054d41a4d24fe9f7599c9d0b66646f7a9984303fd6124044b6206daf831e9a8bda28a6200d318293a13d6c193109b60bd4b4f8b09c90972'
```

## Step 3: OTP Handling & Verification
Depending on your integration type, the OTP can be captured natively on your interface or handled via PayU's fallback page.

### Step Title: Validate OTP and Verify Payment
* **What you need:** Customer-entered OTP, transaction ID (`tranid`), and the Verify Payment API.
* **Instructions:** Submit the OTP to complete the transaction, then call the Verify Payment API from your backend to confirm the final status.
* **Checkpoint:** ✅ Transaction status is updated to `success` or `captured` in your database.

<Accordion title="Verify Payment Status" icon="fa-shield-check">
Always verify the final transaction status using the `verify_payment` API from your server.

```bash
curl --location --request POST '`https://test.payu.in/merchant/postservice.php?form=2`' \
--header 'Content-Type: application/x-www-form-urlencoded' \
--data-urlencode 'key=JPg***r' \
--data-urlencode 'command=verify_payment' \
--data-urlencode 'var1=txnid938459435' \
--data-urlencode 'hash=calculated_hash_value'
```
</Accordion>
