A plan defines the billing schedule for a customer's subscription. In Zion, a subscription can have one or more plans, and each plan controls when invoices are generated, how much is charged, how often the customer is charged, and when that plan should stop.

Use this page when you are building a merchant-facing frontend or dashboard for managing plans. It explains the plan model, the actions you can expose in your frontend, and the API reference pages to use while implementing each action.

<Callout theme="info">
  **Before you begin**: Activate Zion Subscription Automation for your PayU merchant account. To activate Zion, contact your PayU Account Manager.
</Callout>

## What is a plan?

A plan is the billing unit inside a subscription. For example, a customer can subscribe to a base monthly plan and later add another limited-period add-on plan. Each plan runs independently based on its own amount, billing cycle, start date, and total count.

| Plan field | Description | Example |
| :--- | :--- | :--- |
| `planId` | Unique identifier generated for the plan associated with a subscription. | `ZION15728632860122` |
| `planName` | Name of the plan shown in your system and PayU subscription panel. | Premium |
| `billingCycle` | Frequency type for the plan. | MONTHLY |
| `billingInterval` | Interval for the selected billing cycle. | 1 |
| `amount.value` | Amount charged for each billing cycle. | 499.00 |
| `amount.currency` | Currency for the plan amount. | INR |
| `startDate` | Date and time from which Zion can start charging the plan. | 2026-06-01T00:00:00.000Z |
| `totalCount` | Number of billing instances to execute for the plan. | 12 |
| `status` | Current status of the plan inside the subscription. | Active |
| `nextBillingDates` | Next scheduled billing date for the plan. | 2026-07-01T00:00:00Z |
| `lastPaymentDates` | Last successful payment date for the plan. | 2026-06-01T00:00:00Z |

For the complete response field description, refer to [Get Subscription Details API](ref:get-subscription-details-api).

## Frontend actions for plan management

The following actions are commonly exposed in a merchant dashboard or internal frontend for plan management.

| Frontend action | What the merchant can do | API reference |
| :--- | :--- | :--- |
| View plan list | Search and list subscriptions with their plan summaries, customer details, and status. | [Get List of Subscriptions API](ref:get-list-of-subscriptions-api) |
| View plan details | Open a subscription and view plan amount, billing cycle, paid invoices, generated invoices, next billing date, and last payment date. | [Get Subscription Details API](ref:get-subscription-details-api) |
| Create a subscription with plan | Capture customer, mandate, and one or more plan objects while creating a subscription. | [Define Subscription API](ref:create-a-subscription) |
| Create subscription before consent | Define the subscription first and pass the returned subscription ID in the consent transaction so Zion can associate the mandate after consent. | [Define Subscription API](ref:create-a-subscription), [Payment Consent Transaction with Merchant Hosted Checkout](ref:payment-consent-transaction-merchant-hosted) |
| Create subscription after consent | Use the consent transaction response as `authRefId` and then define the subscription with selected plans. | [Payment Consent Transaction with Merchant Hosted Checkout](ref:payment-consent-transaction-merchant-hosted), [Define Subscription API](ref:create-a-subscription) |
| Update subscription information | Update subscription-level values such as `authRefId`, subscriber email, subscriber mobile, or custom parameters. | [Update Subscription API](ref:update-subscription-api) |
| Cancel subscription | Stop the subscription and future processing for all associated plans. | [Cancel Subscription API](ref:cancel-subscription-api) |
| View invoices for a plan | Review invoices generated by Zion for the subscription plan and reconcile payment status. | [Get Invoice API](ref:get-invoice-interfaces-api-zion) |
| Create an ad hoc invoice | Trigger an invoice where your billing use case requires merchant-initiated invoicing. | [Create Invoice API](ref:create-invoice-api-zion) |
| Track lifecycle events | Update the frontend when subscription, invoice, or payment status changes asynchronously. | [Subscription Life Cycle and role of Webhooks](ref:subscription-life-cycle-and-role-of-webhooks-) |

<Callout theme="warn">
  Expose plan edit or plan delete actions only after confirming that your integration has the corresponding backend APIs enabled. When a plan already has generated or paid invoices, validate changes carefully before allowing date, count, or cancellation updates in your frontend.
</Callout>

## Recommended frontend sections

### Plan summary

Show the plan summary wherever a merchant needs to identify the subscription quickly.

Recommended fields:

* Plan name
* Plan ID
* Subscription ID
* Customer email and mobile number
* Billing amount and currency
* Billing cycle and interval
* Plan status
* Next billing date
* Last payment date

Use [Get List of Subscriptions API](ref:get-list-of-subscriptions-api) for listing and [Get Subscription Details API](ref:get-subscription-details-api) for a detailed view.

### Plan creation form

When a merchant creates a new plan for a customer subscription, collect the following details:

| Form field | Backend field | Validation guidance |
| :--- | :--- | :--- |
| Plan name | `subscriptionPlans[].planName` | Use a merchant-readable name for reconciliation. |
| Billing cycle | `subscriptionPlans[].billingCycle` | Use supported values such as DAILY, WEEKLY, MONTHLY, YEARLY, ONCE, or ADHOC. |
| Billing interval | `subscriptionPlans[].billingInterval` | Use `1` for ONCE and ADHOC billing cycles. |
| Amount | `subscriptionPlans[].amount.value` | Use amount format supported by the API. |
| Currency | `subscriptionPlans[].amount.currency` | Use INR where applicable. |
| Start date | `subscriptionPlans[].startDate` | Use ISO 8601 timestamp format in UTC. |
| Total billing count | `subscriptionPlans[].totalCount` | Must represent the number of invoice attempts for the plan. |
| Custom fields | `customParameter` | Use key-value pairs required for your reconciliation. |

For request body details, refer to [Define Subscription API](ref:create-a-subscription).

### Plan detail page

On the plan detail page, show both configuration and progress:

* Configuration: plan name, amount, currency, cycle, interval, start date, and total count.
* Progress: number of generated invoices, number of paid invoices, next billing date, last payment date, and status.
* Subscription context: `subscriptionId`, `authRefId`, subscriber email, subscriber mobile, and custom parameters.
* Available actions: update subscription, cancel subscription, view invoices, and view lifecycle events.

Use the `possibleActions` object returned in [Get Subscription Details API](ref:get-subscription-details-api) to decide which actions to display to the merchant.

### Invoice and payment history

For every plan, provide a section that helps the merchant reconcile charges:

* Invoice ID
* Invoice amount
* Invoice status
* Payment status
* Scheduled billing date
* Payment completion date
* Failure reason, if available

Use [Get Invoice API](ref:get-invoice-interfaces-api-zion) to fetch invoice details. Use webhooks from [Subscription Life Cycle and role of Webhooks](ref:subscription-life-cycle-and-role-of-webhooks-) to keep invoice and payment states updated.

## Plan lifecycle

The plan lifecycle starts when the subscription is defined and ends when all invoices for that plan are attempted or the subscription is cancelled.

1. **Defined**: The plan is added to a subscription request.
2. **Consent pending**: The customer has not yet completed the consent transaction, if consent is collected after subscription creation.
3. **Active**: Zion can generate invoices as per the plan schedule.
4. **In progress**: Invoices are being generated and payment attempts are being processed.
5. **Completed**: All billing instances for the plan have been attempted.
6. **Cancelled or inactive**: The subscription or plan is stopped, and future billing is not processed for it.

<Callout theme="info">
  A subscription can complete only after all invoices for all active plans associated with that subscription are attempted.
</Callout>

## Frontend implementation checklist

Before publishing plan management actions:

* Validate that Zion is enabled for the merchant account.
* Show only actions allowed for the current subscription or plan status.
* Store `subscriptionId`, `planId`, and `authRefId` in your system for reconciliation.
* Keep plan amount, cycle, interval, start date, and total count visible before the merchant submits the action.
* Use webhooks to update asynchronous invoice and payment status.
* Log all frontend actions with the merchant user, timestamp, subscription ID, and plan ID.
* Confirm destructive actions, such as subscription cancellation, before calling the API.
