Merchant Hosted Checkout allows merchants with PCI-DSS compliance to collect credit card credentials directly on their web or mobile checkout page and submit them to PayU.

***

## Step 1: Post Pre-Auth Request to `_payment`

Submit the payment request directly from your application or backend server.

### Environment

| Environment        | URL                                                                                                   |
| :----------------- | :---------------------------------------------------------------------------------------------------- |
| **Test (Sandbox)** | [https://test.payu.in/\_payment](https://test.payu.in/_payment)                                       |
| **Production**     | [https://secure.payu.in/\_payment](https://secure.payu.in/_payment "https://secure.payu.in/_payment") |

### Request Parameters

#### Mandatory Parameters

| Parameter       | Type           | Description                                                                                                                         | Example              |
| :-------------- | :------------- | :---------------------------------------------------------------------------------------------------------------------------------- | :------------------- |
| `key`           | String         | Merchant Key provided by PayU.                                                                                                      | `JPM7Fg`             |
| `txnid`         | String         | Unique transaction ID generated by merchant (Max 25 characters).                                                                    | `CC_PRE_987123`      |
| `amount`        | Float / String | Pre-authorization hold amount (2 decimal places).                                                                                   | `1000.00`            |
| `productinfo`   | String         | Brief product description (Max 100 characters).                                                                                     | `Car_Rental_Deposit` |
| `firstname`     | String         | Cardholder first name.                                                                                                              | `Ashish`             |
| `email`         | String         | Customer email address.                                                                                                             | `ashish@example.com` |
| `phone`         | String         | Customer mobile number.                                                                                                             | `9876543210`         |
| `surl`          | String         | Success callback URL.                                                                                                               | `<redacted URL>`     |
| `furl`          | String         | Failure callback URL.                                                                                                               | `<redacted URL>`     |
| `pg`            | String         | Payment category. Must be set to `CC`.                                                                                              | `CC`                 |
| `bankcode`      | String         | Card network/scheme code: `CC`, `VISA`, `MAST`, or `AMEX`.                                                                          | `CC`                 |
| `ccnum`         | String         | 13–19 digit card number (15 digits for AMEX). Validate with LUHN algorithm.                                                         | `4012888888881881`   |
| `ccname`        | String         | Cardholder name as printed on the card.                                                                                             | `Ashish Kumar`       |
| `ccexpmon`      | String         | Card expiry month in 2 digits (`01` to `12`).                                                                                       | `11`                 |
| `ccexpyr`       | String         | Card expiry year in 4 digits (`YYYY`).                                                                                              | `2027`               |
| `ccvv`          | String         | 3-digit CVV (or 4-digit CID for AMEX cards).                                                                                        | `123`                |
| `pre_authorize` | String         | Set to `1` to perform an authorization hold.                                                                                        | `1`                  |
| `hash`          | String         | Calculated SHA-512 hash: `sha512(key\|txnid\|amount\|productinfo\|firstname\|email\|udf1\|udf2\|udf3\|udf4\|udf5\|\|\|\|\|\|SALT)`. | `d99f23...`          |

#### Optional Parameters

| Parameter       | Type   | Description              | Example                |
| :-------------- | :----- | :----------------------- | :--------------------- |
| `address1`      | String | Billing address line 1.  | `Flat 101, Palm Court` |
| `address2`      | String | Billing address line 2.  | `MG Road`              |
| `city`          | String | Billing city.            | `Bengaluru`            |
| `state`         | String | Billing state.           | `Karnataka`            |
| `country`       | String | Billing country.         | `India`                |
| `zipcode`       | String | Billing postal code.     | `560001`               |
| `udf1` - `udf5` | String | Custom metadata strings. | `Reservation_451`      |

### Sample Request

```bash
curl -X POST "<redacted URL>" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "key=JPM7Fg" \
  -d "pg=CC" \
  -d "bankcode=CC" \
  -d "pre_authorize=1" \
  -d "txnid=CC_PRE_987123" \
  -d "amount=1000.00" \
  -d "productinfo=Car_Rental_Deposit" \
  -d "firstname=Ashish" \
  -d "email=ashish@example.com" \
  -d "phone=9876543210" \
  -d "ccnum=4012888888881881" \
  -d "ccname=Ashish Kumar" \
  -d "ccexpmon=11" \
  -d "ccexpyr=2027" \
  -d "ccvv=123" \
  -d "surl=<redacted URL>" \
  -d "furl=<redacted URL>" \
  -d "hash=CALCULATED_REQUEST_HASH"
```

## Step 2: Handle 3DS Authentication & Callback

1. PayU redirects the customer's browser to the issuing bank's Access Control Server (ACS) for 3DS OTP/PIN authentication.
2. Upon successful authentication, PayU posts the transaction response to your `surl`.
3. Compute the reverse hash to confirm response integrity:
   ```text
   sha512(SALT|status|udf5|udf4|udf3|udf2|udf1|email|firstname|productinfo|amount|txnid|key)
   ```
4. Verify that `status == "success"` and `unmappedstatus == "auth"`. Note the `mihpayid`.

***

## Step 3: Capture Pre-Authorized Funds

Invoke `capture_transaction` via `postservice.php`:

### Mandatory Parameters

| Parameter | Type   | Description                                     |
| :-------- | :----- | :---------------------------------------------- |
| `key`     | String | Merchant Key.                                   |
| `command` | String | Set to `capture_transaction`.                   |
| `hash`    | String | `sha512(key\|capture_transaction\|var1\|salt)`. |
| `var1`    | String | PayU Transaction ID (`mihpayid`).               |
| `var2`    | String | Merchant Transaction ID (`txnid`).              |
| `var3`    | String | Amount to capture (e.g. `800.00`).              |

<Callout icon="⚠️" theme="warn">
  ### **Note**: Any uncaptured balance on card pre-authorizations is automatically released immediately upon executing partial capture.
</Callout>

## Step 4: Verify Transaction Status

Query the transaction using `verify_payment` or verify queued capture actions with `check_action_status`.
