<Callout icon="⚠️" theme="warn">
  UPI Collect is allowed only for MCC 6012 and 6211. Web and Android must use UPI Intent S2S. Seamless form POST does not support Intent. iOS may keep a deeplink and UPI Collect.
</Callout>

***

## Prerequisites

Read [Build the Integration](./index).

***

## Overview of Steps

1. Validate the VPA, then prepare `pg`, `bankcode`, and `vpa`.
2. Generate the hash on the server.
3. Post the form.
4. Verify the reverse hash.
5. Call `verify_payment`.

***

## Build Integration Steps

### Step 1: Prepare Payment Request Parameters

Collect and structure the parameters below before you post a UPI Collect payment. Check the VPA first with `validateVPA`. That call posts to `https://test.payu.in/merchant/postservice?form=2` with `command=validateVPA` and `var1` set to the VPA. Success: `status=SUCCESS`, `isVPAValid=1`. Invalid: `isVPAValid=0`, `payerAccountName=NA`.

    | Parameter | Description |
    | --- | --- |
    | `key` | `string` Merchant key provided by PayU during onboarding. For example, `JPg***r`. |
    | `txnid` | `string` Transaction ID generated by the merchant for this order. For example, `ypl938459435`. |
    | `amount` | `string` Payment amount. For example, `10.00`. |
    | `productinfo` | `string` Brief description of the product. For example, `iPhone`. |
    | `firstname` | `string` Customer's first name. For example, `Ashish`. |
    | `email` | `string` Customer's email address. For example, `abc@payu.in`. |
    | `phone` | `string` Customer's phone number. For example, `9988776655`. |
    | `pg` | `string` Payment category. Must be `UPI`. |
    | `bankcode` | `string` Bank code for this payment option. For UPI Collect, `UPI`. |
    | `vpa` | `string` Customer's VPA. See [UPI Handles](https://docs.payu.in/docs/upi-handles). For example, `test123@okhdfcbank`. |
    | `surl` | `string` Success URL, the page PayU redirects to when the transaction succeeds. The example printed beside this row is `https://example.com/failure`. |
    | `furl` | `string` Failure URL, the page PayU redirects to when the transaction fails. The example printed beside this row is `https://example.com/success`. |
    | `hash` | `string` SHA-512 hash from Step 2. Formula: `sha512(key\|txnid\|amount\|productinfo\|firstname\|email\|udf1\|udf2\|udf3\|udf4\|udf5\|\|\|\|\|\|SALT)`. |

### Step 2: Generate Secure Hash

<Accordion title="Steps to Generate Hash" icon="fa-key">
  Generate the hash on your server. The UPI Collect page uses this order:

  ```text Logic
  sha512(key|txnid|amount|productinfo|firstname|email|udf1|udf2|udf3|udf4|udf5||||||SALT)
  ```

### Step 3: Post the Payment Form

POST the parameters from Step 1 and the hash from Step 2 to `_payment`. The customer approves the collect request in their UPI app.

<Accordion title="POST the HTML Form (server renders)" icon="fa-paper-plane">
  <Cards>
    <Card title="Method">
      POST
    </Card>
    <Card title="Endpoint">
      /_payment
    </Card>
  </Cards>

  | Environment | URL |
  | --- | --- |
  | **Test** | `https://test.payu.in/_payment` |
  | **Production** | `https://secure.payu.in/_payment` |

  Post `pg=UPI`, `bankcode=UPI`, and `vpa`.
</Accordion>

<Accordion title="Success and Error Response" icon="fa-circle-check">
  Sample: `mode=UPI`, `PG_TYPE=UPI-PG`, `bankcode=UPI`, `status=success`, `error=E000`.
</Accordion>

***

### Step 4: Verify Response via Reverse Hashing

The UPI Collect page prints this order:

```text
sha512(SALT|status||||||udf5|udf4|udf3|udf2|udf1|email|firstname|productinfo|amount|txnid|key)
```
