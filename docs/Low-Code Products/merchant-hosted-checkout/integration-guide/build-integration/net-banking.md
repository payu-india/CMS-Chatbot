***

## Prerequisites

Read [Build the Integration](./index). Bank codes are listed in [Net Banking Codes](https://docs.payu.in/docs/net-banking-codes).

***

## Overview of Steps

1. Prepare parameters with `pg` and `bankcode`.
2. Generate the hash on the server.
3. Post the form.
4. Verify the reverse hash.
5. Call `verify_payment`.

***

## Build Integration Steps

### Step 1: Prepare Payment Request Parameters

Collect and structure the parameters below before you post a net banking payment. `pg` and `bankcode` identify the bank.

<!-- VALIDATION NEEDED: The parameter text says pg=NB. The example value is TESTPG. The steps card says pg=NEFT. This page's table describes furl as the success URL and surl as the failure URL. -->

<Tabs>
  <Tab title="Mandatory Parameters and Description">
    These are the mandatory parameters for a net banking payment.<br />

    | Parameter | Description |
    | --- | --- |
    | `key` | `string` Merchant key provided by PayU during onboarding. For example, `JP***g`. |
    | `txnid` | `string` Transaction ID generated by the merchant for this order. For example, `ypl938459435`. |
    | `amount` | `string` Payment amount. For example, `10.00`. |
    | `productinfo` | `string` Brief description of the product. For example, `iPhone`. |
    | `firstname` | `string` Customer's first name. For example, `Ashish`. |
    | `email` | `string` Customer's email address. For example, `abc@payu.in`. |
    | `phone` | `string` Customer's phone number. For example, `9876543210`. |
    | `pg` | `string` Payment gateway. The parameter text says `NB` for NetBanking. The example in the same table is `TESTPG`. |
    | `bankcode` | `string` Bank code for the selected bank. See [Net Banking Codes](https://docs.payu.in/docs/net-banking-codes). The test example is `TESTPGNB`. |
    | `surl` | `string` The source table calls this the failure URL. For example, `https://merchant.com/failure`. |
    | `furl` | `string` The source table calls this the success URL. For example, `https://merchant.com/success`. |
    | `hash` | `string` SHA-512 hash from Step 2. Formula: `sha512(key\|txnid\|amount\|productinfo\|firstname\|email\|udf1\|udf2\|udf3\|udf4\|udf5\|\|\|\|\|\|SALT)`. |
  </Tab>
  <Tab title="Optional Advanced Parameters and Description">
    Send these optional parameters when you collect a billing address.<br />

    | Parameter | Description |
    | --- | --- |
    | `address1` | `string` First line of the billing address. The source says this helps fraud detection and chargebacks. For example, `123 Main Street`. |
    | `address2` | `string` Second line of the billing address. For example, `Apt 456`. |
    | `city` | `string` Billing city. For example, `Mumbai`. |
    | `state` | `string` Billing state. For example, `Maharashtra`. |
    | `country` | `string` Billing country. For example, `India`. |
    | `zipcode` | `string` Billing zip code. Mandatory for cardless EMI. Character limit 20. For example, `400001`. |
    | `udf1` | `string` User-defined field. You can send udf1 through udf5. For example, `custom_value_1`. |
    | `udf2` | `string` User-defined field. For example, `custom_value_2`. |
    | `udf3` | `string` User-defined field. For example, `custom_value_3`. |
    | `udf4` | `string` User-defined field. For example, `custom_value_4`. |
    | `udf5` | `string` User-defined field. For example, `custom_value_5`. |
  </Tab>
</Tabs>

### Step 3: Post the Payment Form

POST the parameters from Step 1 and the hash from Step 2 to `_payment`.
