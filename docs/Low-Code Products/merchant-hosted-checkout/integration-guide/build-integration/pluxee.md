`pg=MC` and `bankcode=SODEXO`. Do not store the full PAN, expiry, or CVV, even with consent.

***

## Prerequisites

Read [Build the Integration](./index).

***

## Overview of Steps

1. Prepare Pluxee fields. Call `check_balance` when you charge a saved card.
2. Generate the hash on the server.
3. Post the form.
4. Verify the reverse hash.
5. Call `verify_payment`.

***

## Build Integration Steps

### Step 1: Prepare Payment Request Parameters

Collect and structure the parameters below before you post a Pluxee payment. Call `check_balance` before you charge a saved card.

<!-- DOCUMENTATION GAP: The check_balance request body is not in this folder. -->

<Tabs>
  <Tab title="Mandatory Parameters and Description">
    These are the mandatory parameters for a new Pluxee card payment.<br />

    | Parameter | Description |
    | --- | --- |
    | `key` | `string` Merchant key provided by PayU during onboarding. For example, `JP***g`. |
    | `txnid` | `string` Transaction ID generated by the merchant for this order. For example, `bvRCCBO4YiGGHE`. |
    | `amount` | `string` Payment amount. For example, `10.00`. |
    | `productinfo` | `string` Brief description of the product. For example, `iPhone`. |
    | `firstname` | `string` Customer's first name. For example, `Ashish`. |
    | `email` | `string` Customer's email address. For example, `test@gmail.com`. |
    | `phone` | `string` Customer's phone number. For example, `9876543210`. |
    | `pg` | `string` Payment category. For Pluxee, `MC`. |
    | `bankcode` | `string` For this card, `SODEXO`. |
    | `ccnum` | `string` 16-digit Pluxee card number. Validate with the LUHN algorithm. For example, `5123456789012346`. |
    | `ccname` | `string` Name on the card. For example, `Ashish Kumar`. |
    | `ccvv` | `string` 3-digit CVV. The source also says 4 digits for AMEX. For example, `123`. |
    | `ccexpmon` | `string` Expiry month in `MM` format. For months 1–9, prepend 0. For example, `10`. |
    | `ccexpyr` | `string` Expiry year in four digits. For example, `2021`. |
    | `surl` | `string` Success URL PayU redirects to if the transaction is successful. For example, `https://example.com/success`. |
    | `furl` | `string` Failure URL PayU redirects to if the transaction fails. For example, `https://example.com/failure`. |
    | `hash` | `string` SHA-512 hash from Step 2. Formula: `sha512(key\|txnid\|amount\|productinfo\|firstname\|email\|udf1\|udf2\|udf3\|udf4\|udf5\|\|\|\|\|\|SALT)`. |
  </Tab>
  <Tab title="Optional Advanced Parameters and Description">
    Send these when you save a card, charge a saved card, or collect the cross-border fields named on the Pluxee page.<br />

    | Parameter | Description |
    | --- | --- |
    | `save_sodexo_card` | `string` Save the card with the payment. `0` does not save. `1` saves. For example, `1`. |
    | `source_id` | `string` Pays with a card saved earlier. Card details are not sent again. For example, `source_12345`. |
    | `is_check_balance` | `string` Check the balance before payment. `0` does not check. `1` checks. Use only with `source_id`. For example, `1`. |
    | `address1` | `string` First line of the billing address. The source says this helps fraud detection and chargebacks, and is mandatory for cross-border payments. For example, `123 Main St`. |
    | `address2` | `string` Second line of the billing address. For example, `Apt 4B`. |
    | `city` | `string` Billing city. The source says this is mandatory for cross-border payments. For example, `Mumbai`. |
    | `state` | `string` Billing state. The source says this is mandatory for cross-border payments. For example, `Maharashtra`. |
    | `country` | `string` Billing country. The source says this is mandatory for cross-border payments. For example, `India`. |
    | `zipcode` | `string` Billing zip code. Mandatory for cardless EMI and, on this page, for cross-border payments. Character limit 20. For example, `400001`. |
    | `udf1` | `string` For cross-border payments, the buyer's PAN when the AD bank requests it. For example, `ABCDE1234F`. |
    | `udf2` | `string` User-defined field for this transaction. For example, `custom_data_2`. |
    | `udf3` | `string` For cross-border payments, the buyer's date of birth in `DD-MM-YYYY` when the AD bank requests it. For example, `15-01-1990`. |
    | `udf4` | `string` For cross-border payments, the end merchant legal entity name. For example, `Merchant Corp Ltd`. |
    | `udf5` | `string` For cross-border payments, the invoice ID or invoice number. For example, `INV_2024_001`. |
  </Tab>
</Tabs>

### Step 3: Post the Payment Form

POST the parameters from Step 1 and the hash from Step 2 to `_payment`.

  | **Production** | `https://secure.payu.in/_payment` |
