`pg=CC`. `bankcode` is network-specific.

***

## Prerequisites

Read [Build the Integration](./index) for the shared hash, reverse hash, and Verify Payment steps.

***

## Overview of Steps

1. Validate the BIN, then prepare card parameters.
2. Generate the SHA-512 hash on the server.
3. Post the form to `_payment`.
4. Verify the reverse hash.
5. Call `verify_payment`.

***

## Build Integration Steps

### Step 1: Prepare Payment Request Parameters

Collect and structure the parameters below before you post a card payment. Call `getBinInfo` first. Test URL: `POST https://test.payu.in/merchant/postservice?form=2`. The prose says `var1=1`, `var2=512345`, `var5=1`. The cURL sends `var1=2`.

<!-- VALIDATION NEEDED: var1 is 1 in the prose and 2 in the sample. Samples use bankcode CC, MAST, AMEX, VISA, and MASTERCARD. The parameter table says ccexpyr is four digits. The cURL sample sends YY. -->

<Tabs>
  <Tab title="Mandatory Parameters and Description">
    These are the mandatory parameters for a card payment.<br />

    | Parameter | Description |
    | --- | --- |
    | `key` | `string` Unique merchant key provided by PayU at registration. For example, `JP***g`. |
    | `txnid` | `string` Unique reference ID generated by the merchant. For example, `ashdfu72634`. |
    | `amount` | `string` Payment amount. For example, `1000.00`. |
    | `productinfo` | `string` Brief description or name of the product. For example, `iPhone`. |
    | `firstname` | `string` Customer's first name. For example, `Ashish`. |
    | `email` | `string` Customer's email address. For example, `test@gmail.com`. |
    | `phone` | `string` Customer's phone number. For example, `9988776655`. |
    | `pg` | `string` Payment gateway. For card payments, use `CC`. |
    | `bankcode` | `string` Issuing bank or network. See [Cards Bank Codes](https://docs.payu.in/docs/cards-bank-codes). For example, `AMEX`. |
    | `ccnum` | `string` 13–19 digit card number. 15 digits for AMEX, 13–19 for Maestro. Validate with the LUHN algorithm. For example, `5123456789012346`. |
    | `ccname` | `string` Name on the card. For example, `Ashish Kumar`. |
    | `ccvv` | `string` CVV. 3 digits for credit or debit cards, 4 digits for AMEX. For example, `123`. |
    | `ccexpmon` | `string` Expiry month in `MM` format. For months 1–9, prepend 0. For example, `10`. |
    | `ccexpyr` | `string` Expiry year in four digits. For example, `2026`. |
    | `surl` | `string` Success URL PayU redirects to after a successful transaction. For example, `https://yourwebsite.com/success`. |
    | `furl` | `string` Failure URL PayU redirects to if the transaction fails. For example, `https://yourwebsite.com/failure`. |
    | `hash` | `string` SHA-512 hash from Step 2. Formula: `sha512(key\|txnid\|amount\|productinfo\|firstname\|email\|udf1\|udf2\|udf3\|udf4\|udf5\|\|\|\|\|\|SALT)`. |
  </Tab>
  <Tab title="Optional Advanced Parameters and Description">
    Send these optional parameters when the payment needs them.<br />

    | Parameter | Description |
    | --- | --- |
    | `address1` | `string` First line of the billing address. The source says this helps fraud detection and chargebacks. For example, `123 Main St`. |
    | `address2` | `string` Second line of the billing address. For example, `Apt 4B`. |
    | `city` | `string` Billing city. For example, `Mumbai`. |
    | `state` | `string` Billing state. For example, `Maharashtra`. |
    | `country` | `string` Billing country. For example, `India`. |
    | `zipcode` | `string` Billing zip code. Mandatory for cardless EMI. Character limit 20. For example, `400001`. |
    | `udf1` | `string` User-defined field for this transaction. You can send udf1 through udf5. For example, `custom_value_1`. |
    | `udf2` | `string` User-defined field. For example, `custom_value_2`. |
    | `udf3` | `string` User-defined field. For example, `custom_value_3`. |
    | `udf4` | `string` User-defined field. For example, `custom_value_4`. |
    | `udf5` | `string` User-defined field. For example, `custom_value_5`. |
    | `store_card_token` | `string` Saved-card network token. The saved-card request also sends `storecard_token_type=1` and `additional_info` with `last4Digits`, `TAVV`, `trid`, and `tokenRefNo`. PayU will not accept a duplicate `txnid`. |
    | `alt_id` | `string` Guest checkout Alt ID. Plain guest card numbers were not allowed after 31 Oct 2023. `additional_info` can include `tavv`, `last4Digits`, `par`, and `tokenReferenceId`. |
    | `threeDS2RequestData` | `string` 3DS 2.0 browser data. The sample also sends `txn_s2s_flow=4`. |
  </Tab>
</Tabs>

### Step 3: Post the Payment Form

POST the parameters from Step 1 and the hash from Step 2 to `_payment`. The customer enters the card on your page. PayU does not show a method-selection page.

<Accordion title="POST the HTML Form (server renders)" icon="fa-paper-plane">
  <Cards>
    <Card title="Method">
      POST
    </Card>
    <Card title="Endpoint">
      /_payment
    </Card>
  </Cards>

  | Environment | URL |
  | --- | --- |
  | **Test** | `https://test.payu.in/_payment` |
  | **Production** | `https://secure.payu.in/_payment` |

  The HTML sample posts `pg=CC` and `bankcode=MAST`. The cURL sample posts `bankcode=CC`.
</Accordion>

<Accordion title="Success and Error Response" icon="fa-circle-check">
  Success: `mode=CC`, `status=success`, `error=E000`, `field7=AUTHPOSITIVE`.

  Failure: `status=failure`, `error=E1903`, `error_Message=Authorization failed at Bank`, `field7=AUTHNEGATIVE`. The sample says `cardhash` is no longer returned.
</Accordion>
